# Caption-Action 0.3.28 — cascade audit

## 1. Root cause (evidence)

| Check | Evidence | Result |
|---|---|---|
| 0.3.26 Live left Whisper source empty | `CaptionOverlayService` had **zero** `setSourceLanguage` calls; Whisper `sourceLanguage=""` → `en-direct` / `auto-translate-en` / `auto-mlkit` | Good Live baseline |
| 0.3.27 forced Live to Input | Overlay setup + every ASR window: `setSourceLanguage(inputLanguage)` → Whisper `language=<input>` `translate=false` (`mic-source-*`) | **Regression** |
| Forced lang hurts when content ≠ Input | Whisper Tiny multilingual relies on `language=auto` (+ optional translate-to-EN). Locking tokens to wrong lang tanks ASR; `translate=false` also drops Whisper→EN path | Matches user report |
| Secondary: MT always preferred Input | `applyPolicy` `sourceCode` branch `input != target → input` first, ignoring script/ASR tag; could MT already-English text as if Chinese | Cascade risk |

**Hypothesis confirmed:** forcing `language=<input>` + `translate=false` on Live is the ASR accuracy regression. Input spinner remains product intent; Live Whisper must stay auto.

## 2. Changes made

- **Live ASR:** `CaptionOverlayService` calls `setSourceLanguage("")` at setup and every window (restore 0.3.13–0.3.26 multilingual policy).
- **Home Input kept:** spinner + `inputLanguage` settings/migration unchanged. Input still drives MT packs (`extraSources`), dual gate (`input≠target`), and ASR-only when `input==target`.
- **MT hint (not lock):** `MlKitTranslationEngine.applyPolicy` — script / reliable ASR tag beat Input; Input used when ASR is `auto`/empty/uncertain. Skip MT when ASR already tagged as target (Whisper `auto-translate-en` / `en-direct`).
- **`likelyNeedsMt`:** still skips when `input==target`; skips when detected==target (non-auto); else wants MT when `input≠target`.
- **Mic:** From/To, FIFO, `translateExplicit`, Whisper meta junk — **untouched**.
- versionName `0.3.28`, versionCode **51**.
